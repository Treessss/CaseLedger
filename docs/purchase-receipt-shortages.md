# 清点入库：确认缺货与分批到货

- 每个变体分别填写本批合格、货损、缺货数量。三者之和不能超过未清点量。
- “剩余缺货”保留本批已填写的合格和货损，把该变体其余未清点量记为缺货；可手动填写部分缺货。
- 保存清点才生效。只有合格品进入实体库存；缺货不入库、不扣库存、不创建采购单。
- 确认缺货立即从在途采购量中扣除，系统按当前库存与所有在途采购重新计算剩余需求，自动进入普通/售后待采购队列。仓库已有可用货时不会重复要求补采。
- 没有标记的数量留待下一批；勾选“最后一批”时，所有剩余未清点量（包括未提交的其他变体）确认缺货并结束本清单。
- 历史已确认缺货不能在原采购单再次收货。补采需另行生成清单，仍可和普通/售后订单一起采购。
- 沿用现有收货接口、店铺权限、店铺/采购单事务锁、批次幂等，不增加数据库字段或修改历史收货数据。

## 数据兼容

采购清单 receipt/allocations JSON 的 `confirmed_missing_quantity` 为累计确认缺货；receipt 的 `pending_quantity` 为尚待清点；receipt 的历史 `missing_quantity` 仍表示未合格/未货损总数（含未清点）。老记录没有新增键时按 0 缺货确认处理，已结束历史清单按原逻辑不计入在途。

本批请求与 receipt_batches.items 使用 `missing_quantity` 表示此次显式标记缺货量；最后一批的隐式剩余量反映于累计收货及分配记录。重复批次必须保持提交数量及 finalize 一致，不会重复入库或释放采购量。
