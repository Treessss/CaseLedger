# 用历史物流账单「近似匹配」已记费订单 + 自动同步方案

## 一、匹配规则（已验证）

实测：4PX `getFreight.create_time`（出账日）≈ 订单北京时间出库日；  
你们费用管理的日账单日 ≈ 4PX 出账日 **+3 天**。

所以近似规则：

> **账单日 D 覆盖：北京时间出库日 = D - 3 的订单**

例：10-22 账单 ¥2,352.04 正好等于 10-25 出账的 4PX 费用合计；10-29 账单 ¥3,201.01 = 11-01 4PX 费用。

说明：

- 旧账单是**每日汇总**，没有订单明细，只能按“出库日期”近似判断覆盖，无法精确到每单金额；
- 无出库时间的 11,433 单是历史迁移订单，无法按日期匹配；建议默认视为“历史已记”，不自动补 4PX 费用；
- 不匹配 ≠ 没付钱，只是账单里没有对应到这一单。

## 三、建议的自动化方案

### 1. 已记费排除
新建覆盖标记表 `logistics_bill_coverage`：
- 把「账单日-3天」对应的订单写入；
- 自动同步任务只处理**不在覆盖表**里的订单；
- 对账页面显示状态「历史账单已覆盖」，不参与补记。

### 2. 后面自动从 4PX 取订单物流费
每天定时（建议 02:00）：
1. 找：已出库、有 4PX 单号、未在覆盖表、订单还没有物流费；
2. 调 `ds.xms.order.getFreight`；
3. 写 `fourpx_freights` 缓存；
4. 订单没有物流费 → 写一条 `order_costs`：
   - `shipping_cost = 4PX 真实总费用`
   - `shipping_source = '4px'`
   - `status = 'pending'`（不自动确认、不扣账户）
   - 记录 4PX 单号和同步时间；
5. 已有手工/账单费用不覆盖；金额不一致只报警。

### 3. 费用管理自动日账单（一天一条）
每天定时（建议 03:00）：
- 汇总前一天出库订单的 4PX 真实费用（按 4PX 出账日）；
- 如果该店铺当天**还没有** `shipping_cost` 费用记录，自动创建一条：
  - `description = 4PX自动-YYYY-MM-DD`
  - `amount = 当日 4PX 真实费用合计`
  - `status = pending/approved`（按你们习惯）
- 已有人工账单的那天**跳过**，绝不重复；
- 一天只写一次（用店铺+日期+标记去重）。

## 四、需要你确认的 3 件事

1. **切换日**：建议 2026-11-01；11 月 1 日之后出库的订单自动同步 4PX 费用；
2. **历史 11,433 单（无出库时间）**：默认视为历史已记，不自动补，对吗？
3. **费用管理自动日账单金额**：用“前一天出库订单的 4PX 真实费用合计”，还是继续用你们现在的 4PX 日账单合计（按账单日）？

确认后我再开自动任务；现在所有匹配都只是只读统计，没有改任何数据。
