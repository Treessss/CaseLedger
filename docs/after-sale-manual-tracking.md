# 售后手动绑定物流

售后列表与详情均提供入口，复用现有售后管理权限及店铺隔离。
`PUT /api/after-sales/<id>/tracking` 参数：

- `tracking_number`：必填，字母、数字、短横线，最多 120 字符；去除首尾空白并转大写。
- `label_barcode`：选填；面单另有 GV 等条码时填写。未填时可按物流单号查询及扫码。
- `expected_tracking_number`、`expected_label_barcode`：打开弹窗时的旧值，首次绑定均为 null。
  与当前值不一致时拒绝，要求刷新，避免并发覆盖。
- `confirm_replace`：替换已绑定单号或条码时必须明确确认。

## 边界

- 仅更新本售后单物流字段与 UTC 更新时间，不更新原订单物流、不通知客户、不改采购或出库状态、不扣库存。
- 不调用 4PX，不核对其客户单号；操作者需人工核对面单。4PX 自动对单仍保留。
- 手动绑定不等于获取了 PDF。4PX 可识别的运单仍可走原获取/批量打印流程；其他物流需自行打印。
- 只绑定运单不填条码时保留空值，不伪造“实体面单条码”；以后获取 4PX 面单可填入真实 GV 条码。
- 相同运单留空条码不清除已核实的旧条码；更换运单不继承旧条码。
- 已出库或已删除售后单不可修改。已回填 Shopify 或结果待确认的售后运单不允许直接换号，可补充条码。
- 新号码不得与其他有效售后或原订单包裹重号；不接受原订单号、CF 单号作为面单号。
  兼容既有合法 CF 覆盖原单的已绑定号码，但不新增原订单碰撞。
- 删除未出库售后单时同时解除物流单号、实体条码，允许重建售后后重新绑定。
  旧号完整保存于 `tracking_unbind` 审计记录（JSON 为原物流号、原条码），不删除采购、库存、费用或物流回填历史。
  已出库历史单（含最后操作为扫码且未撤回的记录）保留号码占用，防止同一面单再次扣库存。
  `release_archived_tracking_bindings(shop_id)` 可幂等清理旧版遗留的未出库已删除绑定；按店铺加锁且保留审计。
- 按店铺→售后单加锁，保存 `outbound_events.action=tracking_bind` 操作记录。
  该类型不计入扫码出库、每日统计及库存扣减。
- 扫码继续走原子实物库存校验，绑定单号不会绕过库存或重复出库限制。

无数据库结构或迁移变更。验证包括重复/过期请求、历史重号、店铺及模块权限、
换号确认、旧条码清理、仅扫码后扣库存，以及绑定前后原订单保持不变。
