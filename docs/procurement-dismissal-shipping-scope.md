# 临时移出采购不影响实物发货

`orders.procurement_excluded_at` 仅抑制当次采购需求，不禁止使用现有库存发货。
保留所有历史标记；不通过清空标记、伪造采购、改仓库状态等方式恢复发货列表。

## 分开计算

- `build_pool_plan()` 默认仍排除被移出采购的订单参与采购需求预测。
- 全部未出库订单独立计算实物库存可满足数量，含被临时移出采购的订单。
  对额外订单统一批量读取实物库存与通用型号元数据，避免逐单重新查询全店库存。
- 订单列表/详情的备货状态使用 `physical_allocations`，而不是采购建议 `allocations`。
- 发货中心及批量面单初始/最终校验使用
  `build_pool_plan(..., respect_procurement_exclusion=False)`：打印建议的库存预算也包含这些订单。
- 默认 `ready_rows()` 使用同一发货口径，不能再次隐式套用采购排除。

## 保留的约束

现有付款、取消、实物出库、部分包裹、通用型号与并发库存扣减规则不变。
发货中心按单判断库存可满足，批量面单按整批数量防止超额；扫码时再次原子校验。
被临时移出的缺货订单仍不进入可发货列表。

人工盘点等原有操作仍可重新开放对应采购需求；手动指定采购仍按原逻辑清除标记。
本次没有修改模型或数据库结构，也没有重写真实订单、库存、采购与出库流水。

## 回归范围

批量临时排除、订单详情备货、缺货禁止发货、采购队列不自动重开、
部分付款/全额退款/取消/已出库约束、批量打印排除标记订单与共享库存不重复预算。
