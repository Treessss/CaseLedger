# 扫码出库异常记录

- 扫码台只显示当前一次提示，不累积红色报错列表；成功后清除提示。
- 重复扫码继续被服务端拦截，但不进入异常记录、不播放失败提示音。
- 仅扫描失败时写入 `outbound_scan_failures`；失败事务先回滚，再单独保存记录。
- 分类：库存不足、未找到面单、面单不齐或不匹配、订单状态不允许、商品或出库流水需核对、系统异常、其他限制。
- 相同店铺、北京时间业务日期、原始扫描条码和分类通过唯一约束合并；次数原子累加，保留首次和最近 UTC 时间。
- 原订单与 CF 售后单各自保留关联。未找到条码时不猜订单，记录中显示“未匹配订单”。
- 查询：`GET /api/shipping/outbound/failures?shop_id=1&date=2026-10-15&category=stock_shortage&page=1`，可加 `search`；履约权限和店铺权限均由后台校验。
- 记录按数据库分页，不限制总条数。扫码过程中不查询历史记录；仅打开“出库异常记录”窗口时查询。
- 网络故障未获得明确响应时，页面提示核对出库状态，不会谎报“已保存异常”。
- “清空”只清除当前提示，不删除历史记录；关闭记录窗口后焦点回到扫码枪输入框。
- 删除员工保留记录，将已删除员工的外键置空；明确强制删除店铺时仅清理该店铺的记录。
