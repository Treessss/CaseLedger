# 采购覆盖与实物出库分开计算

普通订单和售后使用同一套采购预测。已确认/分批到货清单的未清点数量，优先覆盖清单原本的订单/售后需求，不能被普通新订单或发货优先级变化挪走后再次采购。草稿的确认仍需在店铺锁内重新校验。

预测顺序：原需求的在途采购 → 原需求已入库商品（受当前实际库存上限约束）→ 整单可发货的共享库存建议 → 剩余共享库存 → 剩余在途数量。共享覆盖先同型号再通用型号；同一单位实物/在途数量只能计算一次。额外备货和已取消、已出库、换变体后释放的供应仍共享。

清点时货损、确认缺货不计入在途；取消/减量会释放覆盖。已经被别单真实出库或盘点减掉的实物不能用历史入库记录虚构覆盖，实际缺口仍允许补采。采购过不是永久免采购。

这是只读采购预测，不是仓库预占。扫码仍按实际库存动态扣减，不受哪个订单曾采购/建议分配影响。采购待补数量归属可能因此与“单独看此单是否有实物可发”不同；总供应不会重复计算。

历史采购单、清点批次和库存流水不改写，也不自动清理历史重复项。不改表结构。回归覆盖普通订单/售后跨清单防重、到货、缺货重新补采、共享扫码、17/18通用型号和库存守恒。
# 删除售后与草稿清单

已确认采购的货物后来到货时，关联售后可能已使用公共现货出库。收货仍按真实到货登记：
合格品计入公共库存、货损与缺货不计库存；保留售后出库时间、面单和状态，不再扣减出库库存。
售后记录确实缺失或跨店铺、分配明细异常时仍拒绝入库并回滚整个批次。

删除售后单与清理草稿采购需求在同一个事务、店铺锁内完成。仅移除该售后 ID 的分配，
按剩余分配重算商品数量、订单引用和汇总；不能按 CF 文本或变体整行删除，避免误伤
同款原单、其他售后或重新创建后复用 CF 号的新单。空草稿自动取消。

已发起、部分入库、完成的采购快照不改动，列表关联售后号标注“已删除”。有清点数据
或数量不一致的异常草稿拒绝自动清理，删除操作一起回滚。清理写入 PurchaseListEdit
前后快照，重复删除不产生重复扣减；历史软删除可再次调用删除服务完成幂等修复。
